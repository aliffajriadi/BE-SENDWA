Verifikasi nomor WhatsApp

Pastikan nomor WhatsApp user benar-benar miliknya, tanpa mengirim OTP. User yang mengirim kode ke bot, lalu aplikasimu menerima webhook. Cara kerjanya mirip payment gateway.

Karena bot tidak pernah memulai chat, nomor bot jauh lebih aman dari banned dibanding OTP biasa. Secara default bot bahkan tidak merespon sama sekali.

Base URL: https://domain-kamu.com. Semua endpoint di bawah relatif terhadap URL ini.

Alur verifikasi

Minta kodeServer aplikasimu memanggil POST /api/v1/verifications.
Tampilkan ke userArahkan user ke WhatsApp dengan pesan berisi kode VERF-XXXXXX.
User kirim pesanBot mencocokkan kode dan nomor pengirim. Respon ke user opsional (diam, emoji, atau pesan).
Terima webhookServer aplikasimu menerima verification.success dan menandai user terverifikasi.

Kalau webhook tidak sampai, kamu tetap bisa mengecek status lewat endpoint cek status.

Autentikasi

Setiap aplikasi adalah satu project. Admin membuat project di dashboard dan memberikan dua kredensial:

KredensialFormatDipakai untuk
API keypk_live_…Header x-api-key di setiap request ke API.
Webhook secretwhsec_…Memeriksa tanda tangan webhook yang kamu terima.
 
x-api-key: pk_live_xxxxxxxxxxxxxxxxxxxxxxxx

Simpan kedua kredensial hanya di server. Jangan taruh di frontend, aplikasi mobile, atau repository publik. Kalau bocor, minta admin men-generate ulang; yang lama langsung tidak berlaku.

Buat verifikasi

POST/api/v1/verifications

Membuat kode verifikasi baru. Semua field body opsional.

FieldTipeKeterangan
phonestringNomor user (0812…, 62812…, atau +62 812-…). Kalau diisi, hanya nomor ini yang bisa memakai kodenya. Kalau kosong, nomor mana pun bisa, dan nomor pengirim dikembalikan di webhook.
referencestringID dari sistemmu (misal ID user), maks 191 karakter. Dikembalikan apa adanya di webhook.
expires_inintegerMasa berlaku kode dalam detik, 60–86400. Default mengikuti pengaturan project (biasanya 300).
 
curl -X POST https://domain-kamu.com/api/v1/verifications \
  -H "x-api-key: pk_live_xxx" \
  -H "Content-Type: application/json" \
  -d '{ "phone": "081234567890", "reference": "user_123", "expires_in": 600 }'

Cek status

GET/api/v1/verifications/:id

Mengembalikan objek verifikasi terbaru. Pakai ini sebagai cadangan kalau webhook tidak sampai, misalnya polling tiap beberapa detik selama user masih di halaman verifikasi. Hanya bisa membaca verifikasi milik project-mu sendiri.

curl https://domain-kamu.com/api/v1/verifications/cmi8x2k1p0001a8z3 \
  -H "x-api-key: pk_live_xxx"

Error

Error selalu berbentuk JSON { "message": "…" }.

StatusArti
400Input tidak valid, misal expires_in di luar 60–86400 atau phone terlalu pendek.
401Header x-api-key tidak ada atau salah.
403Project sedang dinonaktifkan admin.
404Verifikasi tidak ditemukan (atau milik project lain).
429Terlalu banyak request, maks 60 verifikasi baru per menit per project.
503Bot WhatsApp sedang tidak terhubung. Coba lagi beberapa saat.

Halaman verifikasi

Tidak mau membuat UI sendiri? Redirect user ke verification_url, seperti mengarahkan pembeli ke halaman invoice payment gateway. Di halaman itu user mendapat:

  • Kode verifikasi dan tombol Verifikasi via WhatsApp (pesan sudah terisi).
  • QR code untuk membuka WhatsApp di HP kalau user sedang di laptop.
  • Hitung mundur masa berlaku, dan status yang berubah otomatis menjadi Terverifikasi atau Kedaluwarsa.

Halaman ini hanya menampilkan nama project, kode, status, dan 4 digit terakhir nomor. reference dan data lain tidak pernah ditampilkan. Webhook tetap dikirim seperti biasa.

Admin juga bisa membuat verifikasi manual dari dashboard (Verifikasi WA → Buat Verifikasi) lalu mengirim link-nya ke user.

Pesan WhatsApp

Isi pesan bebas kamu susun sendiri, asal memenuhi dua aturan:

  1. Pesan diawali @ (karakter pertama).
  2. Pesan berisi kode VERF-XXXXXX di mana saja. Huruf besar/kecil tidak masalah.

Respon bot

Admin memilih respon bot per project. Default-nya tidak merespon, karena bot yang tidak mengirim pesan paling aman dari banned. Status verifikasi tetap kamu ketahui lewat webhook atau cek status.

ModeYang diterima user
none (default)Tidak ada respon apa pun.
reactionReaksi emoji di pesan user: ✅ berhasil · ⌛ kedaluwarsa · ❌ nomor tidak sesuai · ℹ️ kode sudah dipakai.
messageBalasan teks. Pesan sukses bisa diatur admin; pesan gagal menjelaskan alasannya (kedaluwarsa, nomor tidak sesuai, sudah dipakai).
@Halo, saya ingin verifikasi akun TokoKu. Kode: VERF-8K2D9Q
✅ Verifikasi VERF-8K2D9Q berhasil. Silahkan kembali ke aplikasi.

Di semua mode, bot selalu diam kalau pesan tidak berisi kode, kodenya tidak dikenal, atau nomor yang sama mencoba lebih dari 5 kali per menit.

Pesan tanpa awalan @ tidak dianggap verifikasi, walaupun berisi kode. Verifikasi hanya lewat chat pribadi, bukan grup.

Webhook

Saat verifikasi berhasil, SendWA mengirim POST ke Webhook URL project. Balas dengan status 2xx dalam 10 detik.

Request ke server kamu
POST /webhook/wa HTTP/1.1
Content-Type: application/json
X-Webhook-Event: verification.success
X-Webhook-Timestamp: 1763719333
X-Webhook-Signature: sha256=5f2b0c…e91a

{
  "event": "verification.success",
  "id": "cmi8x2k1p0001a8z3",
  "code": "VERF-8K2D9Q",
  "phone": "6281234567890",
  "reference": "user_123",
  "verified_at": "2026-11-21T10:02:13.000Z"
}
  • Webhook dikirim sekali. Kalau gagal (timeout / bukan 2xx), statusnya failed. Admin bisa mengirim ulang dari dashboard, atau kamu cek lewat cek status.
  • Proses secara idempoten: webhook yang sama bisa datang lebih dari sekali (misal saat dikirim ulang). Cek id sebelum mengubah data.
  • Kalau project tidak punya Webhook URL, tidak ada webhook. Gunakan polling.

Verifikasi signature

Selalu periksa bahwa webhook benar-benar dari SendWA:

  1. Ambil raw body (string asli, sebelum di-parse JSON).
  2. Hitung HMAC-SHA256(webhook_secret, timestamp + "." + raw_body) dalam hex.
  3. Bandingkan dengan X-Webhook-Signature (tanpa awalan sha256=) memakai perbandingan constant-time.
  4. Tolak kalau X-Webhook-Timestamp lebih dari 5 menit dari waktu sekarang, untuk mencegah replay.
import crypto from "node:crypto";
import express from "express";

const app = express();

// Pakai express.raw supaya body tetap string asli
app.post("/webhook/wa", express.raw({ type: "application/json" }), (req, res) => {
  const ts = req.get("X-Webhook-Timestamp") ?? "";
  const sig = (req.get("X-Webhook-Signature") ?? "").replace(/^sha256=/, "");
  const raw = req.body.toString("utf8");

  const expected = crypto
    .createHmac("sha256", process.env.SENDWA_WEBHOOK_SECRET)
    .update(`${ts}.${raw}`)
    .digest("hex");

  const fresh = Math.abs(Date.now() / 1000 - Number(ts)) < 300;
  const valid =
    fresh &&
    sig.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(sig), Buffer.from(expected));
  if (!valid) return res.status(401).end();

  const event = JSON.parse(raw);
  // TODO: tandai user (event.reference) terverifikasi dengan nomor event.phone
  res.sendStatus(200);
});
use Illuminate\Http\Request;

Simulasi (sandbox)

Saat development, kamu tidak perlu mengirim WhatsApp sungguhan. Minta admin membuat project sandbox (Projects → Edit → Mode sandbox), lalu simulasikan user yang mengirim kode. Hasilnya sama persis dengan verifikasi asli: status berubah jadi verified dan webhook dikirim sungguhan dengan signature yang valid.

Simulasi ditolak (403) untuk project yang bukan sandbox. Pakai project sandbox terpisah untuk development, dan project biasa untuk production.

Lewat API

POST/api/v1/verifications/:id/simulate
FieldTipeKeterangan
phonestringOpsional. Nomor yang dianggap mengirim pesan. Default: phone verifikasi, atau 6280000000000. Isi nomor lain untuk menguji kasus nomor tidak sesuai.
 
# 1. buat verifikasi
ID=$(curl -s -X POST https://domain-kamu.com/api/v1/verifications   -H "x-api-key: pk_live_xxx" -H "Content-Type: application/json"   -d '{"phone":"081234567890","reference":"user_123"}' | jq -r .id)

# 2. simulasikan user mengirim kode → webhook terkirim
curl -X POST https://domain-kamu.com/api/v1/verifications/$ID/simulate   -H "x-api-key: pk_live_xxx"

Response: objek verifikasi dengan status: "verified". Error yang mungkin muncul:

StatusArti
400phone berbeda dari nomor di permintaan verifikasi (sama seperti bot menolak nomor lain).
403Project bukan sandbox.
404Verifikasi tidak ditemukan.
409Kode sudah dipakai.
410Kode sudah kedaluwarsa.

Lewat halaman verifikasi

Untuk project sandbox, verification_url menampilkan tombol Simulasikan verifikasi berhasil. Cocok untuk menguji alur redirect dari awal sampai akhir.

Lewat dashboard

Di Verifikasi WA, verifikasi pending milik project sandbox punya tombol ✓ untuk simulasi. Tombol yang sama juga ada setelah Buat Verifikasi.

Testing

  • Gunakan project sandbox supaya bisa menguji webhook tanpa WhatsApp.
  • Di dashboard admin → Projects, tombol Test membuat kode baru dan membuka WhatsApp, tanpa perlu menulis kode.
  • Untuk menerima webhook di laptop, pakai tunnel (misal ngrok atau cloudflared) lalu isi URL-nya sebagai Webhook URL project.
  • Riwayat dan status webhook ada di dashboard → Verifikasi WA. Webhook yang gagal bisa dikirim ulang dari sana.
